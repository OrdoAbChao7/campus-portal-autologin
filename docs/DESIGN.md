# 设计说明：校园门户自动重登录

## 1. 目标与非目标

**目标**

- 让一个已经由用户本人认证过的出口会话在失效后自动恢复，减少人工登录。
- 在所有情况下都不比人工操作更危险：不暴力尝试、不触发验证码、不影响在线会话。
- 在资源受限的路由器（busybox、无 curl/jq）上可运行。

**非目标**

- 不绕过认证，不破解验证码，不共享账号。
- 不替代学校的无感知/MAC 认证（如果有且可用，应优先用学校的方案）。
- 不实现任意门户的通用适配层；只实现 srun/深澜 v5 的 `/api/account/*` 协议，
  其他门户需要适配器（见 COMPATIBILITY）。

## 2. 状态机

```
                 ┌──────────────────────────────┐
                 │           每 N 分钟           │
                 └──────────────┬───────────────┘
                                ▼
                    GET /api/account/status
                      code==0 且 Username 非空
                       │是                  │否
                       ▼                    ▼
                    退出             GET /api/csrf-token
                 （不写日志）         拿到 token + yudear cookie
                                            │
                                            ▼
                                  POST /api/account/login
                                 （username/password/nasId/
                                   userIpv4/userMac/captcha=空）
                                            │
              ┌─────────────────────────────┼─────────────────────────────┐
              ▼                             ▼                             ▼
           code 0                        code 1                        code 2
       2 秒后复查在线              失败：按次数退避             需要验证码：停 30 分钟
       真在线→成功                 5/10/15…/30 分钟            记录并等待人工登录
       否则只记录                     │
                                     └─ 若消息含“不在线”
                                       且是网关（PORTAL_RECONNECT=1）：
                                       ifdown/ifup WAN（15 分钟最多一次）
                                       → 等最多 60 秒复查
                                       → 仍离线再登录一次
```

## 3. 关键决策

### 3.1 先查状态，在线绝不登录

门户对“重复登录”的处理并不一致：我们实测到门户返回 `code 0`（成功），但原会话随即被
终止，NAS 随后报“设备IP不在线”。因此脚本把“在线”视为硬条件，`attempt_login` 内还有
一次二次检查，防止检查与登录之间的竞争。

### 3.2 nasId 必须来自 BRAS 重定向

未认证时，BRAS 会把任意 HTTP 重定向到形如：

```
http://<portal>/tpl/<school>/login.html?acip=<BRAS-IP>&acname=<BRAS-NAME>
  &ip=<WAN-IP>&nasId=<NAS-ID>&userip=<WAN-IP>&wlanacname=
```

`nasId` 是本端口的接入服务器编号。门户 `/api/config` 的 `default_nas` 只是默认页，
与真实 NAS 无关。用错 nasId 的症状是：登录返回 `code 1 您的设备IP不在线，请断开网络
重新连接后再次登陆`，即使会话确实存在。

脚本的取值顺序：`/etc/portal/nas.conf` → BRAS 重定向（能拿到时）→ `default_nas`。

### 3.3 验证码：遇到即停

`/api/config` 的 `err_count_captcha`（本实现为 10）表示连续错误多少次后出现验证码。
脚本在 `code 2` 时停 30 分钟并记录，绝不尝试识别或绕过验证码；同时失败退避，避免
把正常账号打到触发验证码。

### 3.4 退避

- code 1（密码错、账号锁定、NAS 状态异常）：第 1 次 5 分钟后，第 2 次 10 分钟，
  上限 30 分钟。
- code 2：30 分钟。
- 门户不可达（无 CSRF）：5 分钟。

退避计数在成功或恢复在线后清零。

### 3.5 WAN 重连（仅网关路由器，可选）

某些 NAS 只在链路重新上线时才把设备登记进“在线表”；在此之前，任何凭据登录都会
被拒绝为“设备IP不在线”。脚本在收到该消息时，可选地 `ifdown/ifup` WAN（15 分钟
最多一次），然后等最多 60 秒让 NAS 自行完成 MAC/无感知式恢复；仍不行才再登录一次。

### 3.6 在 PC 上运行

门户按**来源 IP** 认证，PC 在 NAT 后面时来源 IP 是路由器的公网 IP，因此 PC 也能
维持路由器的会话。脚本在不知道 WAN IP/MAC 时省略这两个字段（服务端用来源 IP）。
Windows 版用 DPAPI 加密密码，只能被当前用户解密。

### 3.7 凭据与日志

- 凭据文件 600，root/当前用户所有；密码不出现在命令行、日志、仓库。
- 日志只记录：时间、结果码、nasId、消息（服务端返回的 msg）、切换事件。
- 运行时状态在 `/tmp`（路由器）或 `%APPDATA%`（Windows），不写 flash。

## 4. 失败模式

| 失败 | 检测 | 结果 | 恢复 |
|---|---|---|---|
| 门户地址错误 | 无 CSRF / 无响应 | 5 分钟退避，日志记录 | 修正 PORTAL_HOST |
| nasId 错误 | code 1 设备IP不在线 | 5 分钟退避 | 修正 nas.conf |
| 密码错误 | code 1 其他消息 | 退避直至 30 分钟 | 重新 setup |
| 验证码 | code 2 | 停 30 分钟 | 人工登录一次 |
| 在线但状态接口异常 | 误判离线 | 二次检查拦截；仍可能多一次登录 | 观察日志 |
| 会话被他人顶掉 | status 离线 | 自动登录（除非学校限制） | 正常 |
| 门户改版 | 解析失败 | 记录 unexpected | 更新适配 |

## 5. 测试方法

1. 只读：`status` 必须在在线/离线两种情况下给出正确结果。
2. 受控注销：用会话 token 调 `/api/account/logout`，观察脚本在下一次运行内恢复。
   **会短暂断网**，需明确授权；不要在室友使用网络时做。
3. 失败路径：把 nasId 改成错误值，确认报 `设备IP不在线` 并退避（不要用错误密码，
   避免触发验证码/锁号）。

## 6. 安全边界

- 只操作自己的会话；不枚举、不探测他人。
- 不主动注销会话（测试除外）。
- 不把凭据写进镜像/仓库/日志；发布时使用占位符。
- 代码不做“验证码识别”“账号轮换”“代理共享”。
